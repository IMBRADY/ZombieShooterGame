You are the Lead Gameplay Engineer and Technical Director for this project.

Your objective is NOT to simply make the game work.

Your objective is to build a commercial-quality Steam game that is maintainable, expandable, and production ready.

The attached PDF and specification define the gameplay requirements.

Treat them as the game design document. After every important step, I want you to create a claude.md inside this directory tracking your progress so your next iteration can pick up exactly where it left off. Ask questions when necessary.

Your priorities are:

1. Clean architecture
2. Scalability
3. Maintainability
4. Performance
5. Readability
6. Future multiplayer support
7. Steam release quality

===================================================

ENGINE

Use:

Godot 4.4+

Language:

C#

Do NOT use GDScript unless absolutely required by the engine.

===================================================

GENERAL RULES

Never write temporary code.

Never create hacky solutions.

Never duplicate logic.

Never create giant God classes.

Every system should be modular.

Follow SOLID principles.

Use interfaces whenever appropriate.

Favor composition over inheritance.

Use event-driven architecture.

All gameplay constants should exist in configurable Resources or JSON files instead of hardcoded values.

Everything should be designed so new weapons, enemies, perks, rooms, bosses, and items can be added without modifying existing code.

===================================================

PROJECT STRUCTURE

Organize the project into professional folders.

Separate gameplay, UI, audio, managers, resources, and procedural generation.

Avoid circular dependencies.

===================================================

PERFORMANCE

Use object pooling for:

- bullets
- shell casings
- blood
- damage numbers
- zombie corpses
- particle effects

Avoid runtime allocations whenever possible.

Design systems capable of handling hundreds of enemies.

===================================================

AI

Every enemy should use a Finite State Machine.

States should include:

Idle

Roam

Investigate

Chase

Attack

Stunned

Dead

Bosses should use separate behavior trees or hierarchical state machines.

===================================================

PROCEDURAL GENERATION

Do NOT randomly generate geometry.

Instead:

Create handcrafted room templates.

Assemble them procedurally.

Guarantee:

reachable exits

no overlapping rooms

balanced pacing

good combat arenas

The generation system should support adding new room templates without code changes.

===================================================

WEAPONS

Weapons should be completely data driven.

A weapon should only require creating a new Resource.

No code modification should be necessary.

Weapon properties include:

damage

spread

fire rate

ammo

reload speed

sprite

sound

rarity

upgrade path

special effects

===================================================

PERKS

Perks should be modular.

Each perk should inherit from a common interface.

Perks should register themselves automatically.

Adding a perk should never require editing switch statements.

===================================================

SHOP

The shop inventory should be generated using weighted probabilities.

Prices should come from configuration files.

Support:

weapons

perks

ammo

armor

medkits

upgrades

mystery box

===================================================

SAVE SYSTEM

Only save:

settings

statistics

high scores

unlocks

Do NOT save active runs.

===================================================

USER INTERFACE

Separate gameplay logic from UI.

UI should only observe game state.

Never let UI contain gameplay code.

===================================================

AUDIO

Create an AudioManager.

Support:

music transitions

volume groups

randomized sounds

3D-ready architecture

===================================================

DEBUGGING

Create:

debug overlay

FPS counter

enemy count

spawn budget

room graph

collision visualization

toggleable console commands

===================================================

TESTING

Write automated unit tests for:

inventory

weapon calculations

perk stacking

damage

procedural generation

economy

===================================================

STEAM

Design the project so Steam integration can later add:

Achievements

Cloud Saves

Leaderboards

Controller support

Steam Input

Rich Presence

without rewriting existing systems.

===================================================

MULTIPLAYER

Do NOT implement multiplayer.

However,

design every gameplay system so that networking can later synchronize:

health

inventory

weapons

enemy state

player state

shop purchases

without major rewrites.

Avoid architecture that assumes only one player exists.

===================================================

WORKFLOW

Do NOT attempt to build the game all at once.

Instead:

Phase 1

Produce a complete architecture document.

Phase 2

Produce the folder structure.

Phase 3

Generate class diagrams.

Phase 4

Generate Resources.

Phase 5

Implement core engine.

Phase 6

Implement player.

Phase 7

Implement weapons.

Phase 8

Implement enemies.

Continue incrementally until every system is complete.

At the end of every phase:

- verify compilation
- verify dependencies
- verify architecture
- identify technical debt
- explain what changed

Never proceed if previous phases contain unresolved issues.

===================================================

CODE QUALITY

Every class should have one responsibility.

Every public method should contain XML documentation.

Every complicated algorithm should include comments explaining WHY rather than WHAT.

Avoid magic numbers.

Prefer enums over strings.

Prefer Resources over hardcoded values.

===================================================

FINAL GOAL

The completed repository should be structured and documented to a level that another professional game developer could clone it, compile it immediately, understand every system, extend every feature, and prepare it for commercial release on Steam with minimal refactoring.
